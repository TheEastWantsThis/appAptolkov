# Ключевые принятые допущения

Эти допущения дополняют [ARCHITECTURE.md](./ARCHITECTURE.md) и [ACCESS-WORKFLOWS.md](./ACCESS-WORKFLOWS.md). Они нужны там, где исходные требования допускают несколько трактовок, и должны быть подтверждены на этапе 0.

1. **Продажная и финансовая информация.** Продажная цена актуальной сметы и договорная сумма трактуются как коммерческие данные, необходимые AD_OPERATOR для согласования договора. Закупочная цена, себестоимость, прибыль, платежи, расходы и финансовые отчёты трактуются как финансовые данные и AD_OPERATOR недоступны. Если правило «финансовую информацию видят только ADMIN/FINANCE_MANAGER/MANAGER» включает также продажную цену, подготовку и подписание договора следует перенести от AD_OPERATOR к MANAGER/FINANCE_MANAGER; матрица и переходы должны быть изменены до кода.
2. **Финансовый статус проекта.** `Project.financialStatus` использует значения `NOT_DUE`, `UNPAID`, `PARTIALLY_PAID`, `PAID`, `OVERPAID`, `REFUND_DUE`, `WRITTEN_OFF`. Значение вычисляется сервером из действующей договорной суммы и POSTED платежей/возвратов; ручное редактирование запрещено.
3. **Телефон.** FINANCE_MANAGER не получает полный телефон по роли автоматически: требуется отдельный пользовательский `customer.phone.read`. MANAGER не получает полный телефон даже при широком доступе к проектам, пока исходное правило не будет явно изменено.
4. **Центральный workflow.** `Lead` не имеет независимого бизнес-статуса: публичный статус лида — безопасное отображение `Project.status`. Это исключает рассинхронизацию двух автоматов.
5. **Склад.** `onHand` включает выданное, но ещё не потреблённое имущество компании. По локациям используется поддерживающая сущность `InventoryBalance`; `InventoryItem` содержит глобальный кэш. Отрицательные остатки в базовой конфигурации запрещены.
6. **Калькулятор.** Коэффициент сложности применяется только к тарифным строкам с признаком `complexityApplicable`; выезд не участвует в скидке и минимальной стоимости заказа; округление выполняется по строкам. Все три правила версионируются и требуют бизнес-подтверждения.
7. **PWA.** Первая версия работает онлайн для рабочих данных. Офлайн кэшируется только оболочка без PII; офлайн-очередь заявок с телефонами не реализуется без отдельной модели угроз и правил разрешения конфликтов.
