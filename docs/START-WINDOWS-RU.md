# Запуск CRM на Windows и временный показ через интернет

Эта инструкция рассчитана на Windows 10/11 и человека без опыта администрирования. Проект можно запускать на текущем компьютере или перенести на старый ноутбук и использовать его как небольшой сервер.

## Что уже автоматизировано

В корне проекта находятся три файла:

- `START-CRM.cmd` — запускает PostgreSQL и CRM только на компьютере и в домашней сети;
- `START-DEMO-INTERNET.cmd` — запускает CRM и создаёт временную публичную HTTPS-ссылку;
- `STOP-CRM.cmd` — останавливает CRM и PostgreSQL, не удаляя данные.

Скрипт запуска автоматически:

1. создаёт `.env` и безопасный `AUTH_SECRET`, если файла ещё нет;
2. запускает Docker Desktop и PostgreSQL;
3. устанавливает npm-зависимости, если их нет;
4. генерирует Prisma Client и применяет миграции;
5. создаёт администратора и демонстрационные данные только в пустой базе;
6. выполняет production build, если исходный код изменился;
7. запускает CRM на порту 3000.

## Первый запуск на этом компьютере

1. Откройте папку проекта.
2. Дважды нажмите `START-CRM.cmd`.
3. Не закрывайте окно во время первого запуска. Установка и сборка могут занять несколько минут.
4. Когда появится сообщение `CRM работает`, откройте http://localhost:3000.

Если Windows спросит разрешение для Docker или Node.js в брандмауэре, разрешите доступ только для частных сетей.

## Запуск после выключения или перезагрузки

Каждый раз после включения компьютера:

1. дождитесь полной загрузки Windows;
2. дважды нажмите `START-CRM.cmd`;
3. откройте http://localhost:3000.

Повторно устанавливать Node.js, Docker, базу или зависимости не нужно. Все данные PostgreSQL сохраняются в Docker volume `apotolkov_postgres_data`.

Чтобы корректно завершить работу, дважды нажмите `STOP-CRM.cmd`, дождитесь сообщения об остановке и только затем выключайте компьютер.

## Временный показ через интернет

1. Дважды нажмите `START-DEMO-INTERNET.cmd`.
2. Скрипт пересоздаст отдельную базу `apotolkov_demo` только с искусственными данными.
3. Дождитесь адреса вида `https://случайные-слова.trycloudflare.com`.
4. Отправьте этот адрес человеку, которому хотите показать CRM.
5. Ссылка продолжит работать в фоне, пока компьютер включён и подключён к интернету.
6. Адрес также сохраняется в `.runtime\public-url.txt`.
7. Для завершения запустите `STOP-CRM.cmd`.

Quick Tunnel бесплатен, не требует аккаунта или домена, но предназначен только для тестов. Адрес меняется при каждом запуске, гарантии доступности нет, действует ограничение Cloudflare на 200 одновременных запросов. Официальная документация: https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/

Не публикуйте в демо настоящие телефоны клиентов, финансовые данные или документы. Передавайте тестовые учётные данные только людям, которым доверяете.

## Доступ с телефона в одной Wi-Fi сети

1. На серверном компьютере нажмите `Win + R`, введите `cmd` и нажмите Enter.
2. Выполните `ipconfig`.
3. Найдите `IPv4-адрес`, например `192.168.1.25`.
4. На телефоне, подключённом к тому же Wi-Fi, откройте `http://192.168.1.25:3000`.

Если адрес не открывается, разрешите Node.js для частной сети в брандмауэре Windows. Не открывайте порт 3000 на роутере — для доступа из интернета используйте только туннель.

## Установка на пустой старый ноутбук

Установите по очереди:

1. Git for Windows: https://git-scm.com/download/win
2. Node.js LTS: https://nodejs.org/
3. Docker Desktop: https://www.docker.com/products/docker-desktop/

После установки перезагрузите ноутбук. Затем откройте PowerShell и выполните:

```powershell
git clone https://github.com/TheEastWantsThis/appAptolkov.git
Set-Location appAptolkov
npm ci
Copy-Item .env.example .env
```

После этого дважды нажмите `START-CRM.cmd`. Если проект ещё не отправлен в GitHub, сначала скопируйте всю папку проекта на ноутбук флешкой, исключив папки `node_modules` и `.next`, затем запустите `npm ci`.

Для слабого ноутбука желательно иметь SSD и не менее 8 ГБ памяти. После успешной production-сборки CRM работает заметно легче, чем режим разработки.

## Как дорабатывать на основном компьютере, а запускать на ноутбуке

На основном компьютере после проверенных изменений:

```powershell
git add .
git commit -m "Описание изменений"
git push
```

На ноутбуке:

```powershell
Set-Location C:\путь\к\appAptolkov
git pull
```

Затем запустите `START-CRM.cmd`. Скрипт сам применит новые миграции и пересоберёт приложение, если исходный код изменился.

Перед `git pull` создавайте резервную копию базы. Не храните `.env`, дампы базы и реальные пароли в Git.

Вход выполняется по номеру телефона и паролю.

| Роль                | Телефон            | Пароль   |
| ------------------- | ------------------ | -------- |
| Администратор       | `+7 999 000-00-01` | `Adm001` |
| Промоутер           | `+7 999 000-00-02` | `Dem001` |
| Оператор            | `+7 999 000-00-03` | `Dem001` |

После показа назначьте другие пароли через администратора.

## Где смотреть ошибки

Логи production-сервера находятся в:

- `.runtime\logs\crm-out.log`;
- `.runtime\logs\crm-error.log`.

Проверка базы:

```powershell
docker compose ps
docker compose logs postgres
```

Проверка приложения:

```powershell
npm run typecheck
npm run lint
npm run test:unit
npm run test:integration
npm run build
```

## Резервная копия перед переносом или обновлением

```powershell
docker compose exec postgres pg_dump -U apotolkov -d apotolkov -Fc -f /tmp/apotolkov.dump
docker cp apotolkov-postgres:/tmp/apotolkov.dump .\apotolkov.dump
```

Файл `apotolkov.dump` храните отдельно от ноутбука. Для реального постоянного использования вместо временного Quick Tunnel нужен стабильный домен, именованный Cloudflare Tunnel, регулярные резервные копии и обновления Windows/Docker/cloudflared.
