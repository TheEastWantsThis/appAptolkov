# Аудит безопасности и готовности MVP

Дата проверки: 2026-08-03.

## Права доступа и IDOR

- Защищённые queries и Server Actions вызывают requirePermission или проверяют назначение текущего пользователя.
- Замеры и монтажи фильтруются по measurerId или participants.userId; чужой UUID не расширяет доступ.
- Уведомления изменяются через updateMany одновременно по id и userId.
- Финансы, склад и общая аналитика имеют отдельные permissions.
- Промоутерская аналитика принудительно использует authorId текущей сессии.

## Телефоны и финансы

- Полный телефон выдаётся только через customer.phone.read; остальные DTO возвращают маску.
- Кабинет монтажника не выбирает customer, lead, estimate или finance.
- Кабинет замерщика не выбирает телефон и финансовые агрегаты.
- Клиентский PDF не содержит себестоимости.
- Финансовые поля загружаются только после finance.read; изменения требуют finance.manage и пишутся в AuditLog.

## Файлы

- Формы принимают только HTTPS-ссылки.
- javascript:, file: и нестандартные схемы отклоняются.
- Server Actions ограничены bodySizeLimit 1mb.
- Бинарный upload в MVP не реализован; production-требования описаны в README.

## Конкурентные операции

- Финансы и склад имеют поле version.
- Изменение выполняется условным updateMany по идентификатору и версии.
- Устаревший запрос получает CONFLICT, а не перезаписывает свежие данные.
- Integration-тест проверяет отклонение второй складской записи с устаревшей версией.

## State machines

- Проекты и монтажи используют явные таблицы переходов.
- Проект не завершается при открытых задачах, незавершённых монтажах или непогашенных финансовых условиях.
- Для завершения монтажа нужны фактическое начало, фото после, подпись и приёмка.

## Мобильная адаптация

- Основные формы используют одноколоночную раскладку на телефоне.
- Нижняя навигация ограничена пятью пунктами; экран «Ещё» открывает остальные разрешённые разделы.
- Playwright проверяет мобильную навигацию и отсутствие горизонтального overflow.

## Производительность

- Аналитика ограничивает период и выбирает только необходимые поля.
- Добавлены индексы по источнику и дате, истории статусов и интервалам календаря.
- Списки имеют ограничение записей; при росте данных аналитика переносится в materialized views.

## Обработка ошибок и TypeScript

- Проект работает в TypeScript strict без any.
- Формы валидируются Zod на серверной границе.
- Пользователь получает понятные ошибки VALIDATION, FORBIDDEN, NOT_FOUND и CONFLICT.
- Необработанные подробности не возвращаются клиенту.

## Тестовое покрытие

- Unit: RBAC, приватность телефона, state machines, калькуляторы, финансы, склад и HTTPS URL.
- Integration: ограничения PostgreSQL и optimistic concurrency.
- Playwright: вход, общая и личная аналитика, мобильная навигация.
- Production build входит в обязательный финальный конвейер.

## Остаточные риски

- В MVP нет бинарного storage-адаптера и антивирусного сканирования; принимаются только ссылки доверенного HTTPS-хранилища.
- Агрегаты аналитики вычисляются on-demand; для больших объёмов потребуются очереди и materialized views.
- npm audit сообщает advisories транзитивных зависимостей актуального Next.js; несовместимый принудительный downgrade не применяется.
